# pair-wise-yy-61 航空器定检工作包执行与放行审阅平台

支持工卡依赖、测量值容差校验、离线暂存、冲突提交提示、分阶段签字、版本差异和放行锁定。超差项目必须由授权人员处理后才能继续。

## 授权链（工卡 → 阶段签字 → 人员资质/代班 → 放行基线）

实现在 `src/auth/`：

- `domain.ts`：纯领域规则。签字前校验人员在岗、资质在有效期、班次名册或有效代班关系；质量阶段（系统/放行）强制执行与复核不得为同一人，并与工卡登记施工人交叉比对。
- `seed.ts`：人员资质、班次名册、代班关系与两条旧签字（一条可按名册回填、一条名册查无此人留待换签）。
- `flows.ts`：签字编排 thunk。登记人员/资质号/资质有效期/代班关系；服务端按「阶段+角色」槽位仲裁，先到生效、后到保留待复核（可确认或驳回）；同事件号重放幂等不多签；写入失败保留原草稿与事件号，恢复后重试。
- 授权范围变化（资质撤回、人员换岗、代班停用）后，未放行工卡的相关签字**立即失效并回到待签**，同时释放服务端槽位；已放行基线只保留放行当时的只读快照，不受后续变化影响。
- 旧签字无资质号时按班次名册反查回填；回填不通过标记「待换签」，由当前授权人员换签。
- 放行门禁：四阶段签字有效、无待复核/待换签/失效签字、关键工卡完成、无待授权超差。全部通过才允许锁定并生成基线。

### 演示路径

1. 总览页可见旧机械签字已按名册回填（赵明 CQ-ME-0108），另一条留待「待换签」（放行页可切换到中班机械师孙磊换签）。
2. 放行页以当前登录人签署：系统阶段先执行（林岚）后复核（周正）；周正不能复核自己执行；并发按钮可在授权管理页模拟两人同时提交（先到生效、后到待复核）。
3. 动力阶段：陈骁资质已过期被拦；夜班韩松凭代班关系 ACT-09 可签。停用代班关系后其签字立即失效。
4. 「模拟写入失败」后提交签字：草稿与事件号保留，恢复在线后原事件号重试，不产生重复签字。
5. 授权管理页撤回资质/换岗：相关未放行签字立即回待签；先完成放行再撤回，则基线快照保留。

## 技术栈

React、Fluent UI、Redux Toolkit（含 thunk 编排）、React Router、RTK Query（mock 服务端槽位仲裁）、Vite、TypeScript。

## 运行

```bash
npm install
npm run dev
```

访问 `http://localhost:62061`。授权链状态保存在 `localStorage`（键 `yy61-auth-chain-v2`，授权管理页可重置演示数据）。

```bash
npm run build
```
